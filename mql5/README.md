# 検証用EA：AON_MACross

AlgoOps NoteのPoCで、検証パイプラインの題材として使うEAである。売買ルールは移動平均線のクロスという広く知られた手法にとどめ、独自の工夫は加えない。目的は勝てるEAを作ることではなく、バックテスト・最適化・レポート解析の流れを、条件をそろえて繰り返し試せるようにすることにある。

ストラテジーテスターとデモ口座での利用に限る。リアル口座では、テスター以外で起動すると初期化の段階で停止する。

## 売買ルール

| 項目 | ルール |
|---|---|
| エントリー | 短期EMAが長期EMAを上抜けたら買い、下抜けたら売り |
| 判断のタイミング | 新しい足が始まったときに1回だけ。直前の確定足2本で判定する |
| 決済 | 逆方向のクロスで決済し、そのまま反対方向に建て直す（ドテン）。ATRで決めた損切り・利食いに先に達した場合はそこで決済する |
| 損切り | エントリー価格からATR×`InpSlAtrMult` |
| 利食い | エントリー価格からATR×`InpTpAtrMult`（0なら設定しない） |
| ロット | 損切りに達したときの損失が、残高の `InpRiskPercent` %になる量。端数は切り捨てる |
| ポジション数 | 通貨ペアごとに最大1つ。マジックナンバーで自分のポジションを見分ける |
| スプレッド | `InpMaxSpreadPoints` を超えるときは新規エントリーだけを見送る |

## 検証用としての設計

判断を確定足に限ったのは、足が確定する前の値動きでシグナルが変わらないようにするためだ。テスターのモデルには全ティック、リアルティック、始値のみなどがある。シグナルを確定足で決めておけば、モデルを変えたときの結果の違いは、主に損切りと利食いの約定のされ方から生じる。モデルの違いを比べる記事を書くときに、原因を切り分けやすい。

ロットを残高に対する比率で決めるのは、期間や通貨ペアを変えた検証どうしを比べやすくするためである。固定ロットにすると、口座通貨と価格水準の違いがそのまま損益の大きさに出てしまう。

最適化の評価値として `OnTester()` を実装している。値はリカバリーファクター（純利益÷最大ドローダウン）で、取引回数が `InpMinTradesForScore` に満たない組み合わせは0にする。取引回数が少ない組み合わせが偶然の好成績で上位に並ぶことを避けるためだ。テスターの最適化基準で「カスタム最大」を選ぶと、この値が使われる。

## パラメータ

| パラメータ | 既定値 | 意味 |
|---|---:|---|
| `InpFastPeriod` | 20 | 短期EMAの期間 |
| `InpSlowPeriod` | 50 | 長期EMAの期間。短期より大きくなければ起動しない |
| `InpAtrPeriod` | 14 | ATRの期間 |
| `InpSlAtrMult` | 2.0 | 損切り幅のATR倍率 |
| `InpTpAtrMult` | 3.0 | 利食い幅のATR倍率。0なら利食いを設定しない |
| `InpRiskPercent` | 1.0 | 1回の取引で許容する損失（残高に対する%）。上限10 |
| `InpMaxSpreadPoints` | 30 | 新規エントリーを許すスプレッドの上限（ポイント）。0で無効 |
| `InpMagic` | 20261121 | マジックナンバー |
| `InpMinTradesForScore` | 30 | `OnTester()` が評価値を返すのに必要な最小取引回数 |
